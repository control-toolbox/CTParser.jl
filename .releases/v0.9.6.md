## Release proposal — CTParser v0.9.6 (stable)

**Version.** Last release `0.9.5-beta`; last version in General `0.8.15`. Since `0.8.15` (the reference of a stable, `REL2`): breaking changes and new features, carried by the betas `0.9.0` to `0.9.5-beta` and by `[Unreleased]`. A breaking stable after `0.8.15` is `0.9.x`; the betas took `0.9.0` to `0.9.5`, a stable never takes the triple of a beta, so the version is **`0.9.6`** (`release.jl facts`: the expected version).
**Jump in General (`REL3`).** `0.8.15` → `0.9.6`: skipped `0.9.0` to `0.9.5`, all betas in ct-registry: `[merge approved]` needed on the General PR.
**Resolves from General alone (`REL4`).** ✅
**Versions applied.** ct-agents `v0.4.0` (the recipe, with control-toolbox/ct-agents#25), ct-conventions `v0.10.0`, CTActions `f707bb3` (the release tool, control-toolbox/CTActions#154).

### What changes since `0.9.5-beta`

- 💥 The prefix API is removed (#356): the code generated by `@def` and `@init` refers to `CTModels`, `ExaModels` and `CTBase` by module object, so it works from any caller module (`import OptimalControl` no longer fails); `CTModels` and `ExaModels` become direct dependencies. Migration in `BREAKING.md`.
- 🐛 Parser errors: a redefined alias is named (#420); a state or control used without a time, or at a wrong time, is rejected (#193, #139); trace mode shows the user's names (#354); `:exa` accepts the scheme aliases of `:adnlp` (#355); a better hint for a bound that depends on the state, control, variable or time (#352); `u = (z,) ∈ R` is rejected (#4).
- 🛠 No allocation on a vector literal in the `:fun` functions (#21); linear algebra with `Diagonal`, sparse and static constants in `:exa` (#365), with two companion extensions; typed errors from the ExaModels extension.
- 📦 `DocStringExtensions` 0.10 supported (#384; the entry was missing, added by this request).
- Since `0.8.15` (the betas): see the sections `0.9.0` to `0.9.5-beta` of the changelog.

### The review

23 candidates from `release.jl facts`: 20 covered by the changelog, 1 entry added (`DocStringExtensions`, #384), 2 not user-facing (the bounds of the standard libraries `LinearAlgebra` and `SparseArrays`, which come with the weak dependencies). Among them, 7 entries outside `💥` whose words read like a break ("no longer", "renamed", "deprecated"): none is one; the rename of the function behind `@def_exa` (#389) is internal (not public, called by no downstream package), the exception type of `tr` is in the non-breaking note of `BREAKING.md`. 21 merged PRs ship nothing (CI, pins, README, tests).

### What happens

The `Release` workflow (`supervised`): the tracking issue; the release PR once `main` is green (approval 1); the checks; the merge with `release.jl merge` (approval 2); the tag; the registration comment (approval 3); General's PR, where you comment `[merge approved]`; the close and the audit.
